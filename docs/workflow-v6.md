# V6 AI 辅助运维工作台：业务对应与调整说明

依据：用户提供的《AI工作台_Demo业务流程固定要求.md》（2026-10-26），以及用户随后确认的“先做一套完整新版”“光伏、储能、风电资产”“光伏逆变器绝缘异常”案例。

原固定要求文件未修改。8 个正式环节、责任角色、5 类智能体及许可后的现场执行全部保留。

## 页面与业务对应

| 环节 | 责任人 | AI 材料 | 人员决策 / 交接 |
| --- | --- | --- | --- |
| 01 故障确认 | 运行人员 | 根因假设、趋势、降雨与支路比对、风险、两种范围方案 | 认可缺陷、选择方案，可请求外观复核；移交检修组长 |
| 02 工单复核与派单 | 检修组长 | 推荐时间、候选人员、巡检冲突、物资清单 | 调整时段、执行人和监督员，确认派单或退回 |
| 03 工作票提交 | 检修人员 | 工序、安全措施与工作票草稿 | 编辑工序和时间，确认提交审批 |
| 04 工作票审批 | 检修组长 | 提交稿对比、范围与措施检查、交叉作业提示 | 核查范围、措施、并行风险，批准或退回 |
| 05 操作票提交 | 检修人员 | 停运与隔离步骤、顺序校验、影响和风险 | 编辑并排序操作项，确认提交许可 |
| 06 操作票审批 | 值长 | 提交稿校验、停电影响、复电条件 | 核查后许可或不许可 |
| 现场执行（不编号） | 执行人 / 监督员 | 获批票据与范围汇总 | 接收许可、记录处理与复测、提交验收材料 |
| 07 工单结案 | 检修组长 | 前后数据、复测趋势、工时、质量汇总 | 验收结案或要求补充复测 |
| 08 知识沉淀 | 检修组长 | 案例草稿、经验与改进建议、关联材料 | 补充经验，确认入库；此时才标记故障闭环 |

智能体严格按缺陷 → 排程 → 两票 → 验证 → 知识接续。现场执行展示两票交接材料，不增加第六类智能体，也不把现场作业设为 AI 自动执行。

## 调整及理由

1. **将水电机组案例换成光伏逆变器绝缘异常。** 用户明确实际资产为风光储；水轮发电机、冷却水泵和官地机组不适合作为新版主案例。新版首页仅使用光伏阵列、风机和储能柜，设备页使用逆变器结构示意。
2. **新建独立入口，保留原三方向方案。** 本次从视觉比较转向业务完整性，避免在原九页上硬塞工作票与审批；V5 可继续通过 compare.html 查看。
3. **中间 AI 材料、右侧人员决策、左侧流程。** 让依据、可修改内容和责任人的确认动作同时可见。操作后保留结果与下一责任人提示。
4. **用显式角色交接替代自动推进。** 每一步确认后不会代替下一角色审批。点击“切换并接续”是演示角色切换，不是生产身份认证。
5. **新增退回、暂缓与补充复测的可操作演示。** 这些不是正式环节扩展，而是落实固定要求中的关键决策。退回会使对应提交及后序审批失效；复测回到现场阶段，保留此前已获许可。
6. **现场复核与许可后作业分开。** 故障确认中的复核仅为外观巡检反馈；不能因此跳过两票许可。正式检查和处理必须在许可后开始。
7. **保留提交快照和历史材料。** 已完成环节只读，退回不覆盖历史动作。每次提交记录保留材料副本，可区分首次不合格复测与后续合格复测。
8. **图表按像素重新绘制，窄屏转内容流。** 避免文字和圆点随 SVG 拉伸；小高度桌面分区滚动，窄屏按材料、决策顺序排布，不压缩字号强塞一屏。

## 演示规则与边界

- 主案例是虚构的柯拉光伏 7# 逆变器 / 3B 支路。假设受潮原因，现场核实前不会写成确定根因，也不提供虚构的诊断置信度。
- 2.48 → 0.16 MΩ 与修复后 1.64 MΩ 均为示例；1.0 MΩ 明确标为“示意阈值”。实际设备定值未在本项目中核验。
- 工作票和操作票采用流程层级描述，不作为真实电气操作规程。设备结构不是厂商 CAD，资产图不是 GIS。
- 排程的已知冲突为相邻巡检 14:00—14:20；执行与监督不能同人。工作票改时段时也检查这一冲突，现场展示工作票批准后的时段。
- 操作顺序按固定演示规则校验；AI 材料为本地预置内容与确定性规则，不是实时大模型推理。
- 工单结案不自动入库。必须再由检修组长确认知识沉淀。
- 现场记录初始为空；开始执行后可手动填写，或明确点击“载入现场示例记录”演示。AI 不预填已经发生的现场事实。
- 刷新保存进度；仅“重置演示”清空本浏览器内的案例状态。处理记录可导出 JSON，包含材料快照。

## 实现与验证

入口 ai-workbench.html；workflow-app.js 负责工作区，workflow-state.js 管理状态及门槛，energy-scene.js 为风光储与逆变器场景，workflow-charts.js 按容器绘图。

`npm test` 检查关键业务门槛和回退。浏览器实测记录及预览图存于 artifacts-v6/，包含正常闭环、退回、不许可、补充复测、角色交接、刷新持久化和多尺寸布局。
